2. MD（模式粗选）与 RDO（精细优化）的彻底解耦设计

这是硬件编码器实现极速并行计算的最核心架构优化。为了打破“当前 CU 预测必须等待前一个 CU 重建完毕”的空间串行死锁，硬件设计采用了**两阶段选拔制**。

4. 痛点解析一：MPM 的强依赖流水线气泡

💡 什么是 MPM (Most Probable Mode) 算法？
MPM 是一种利用空间相邻性来压缩模式编码比特数的算法。核心思想是：当前块的纹理方向极有可能与它左侧和上方的相邻块保持一致。因此，编码器会根据左块和上块的最终预测模式，推导出一个“最可能模式列表”。如果当前块最优模式在这个列表中，只需极少比特即可编码。

// MPM Pseudocode (Algorithm Logic)
function derive_mpm_list(left_block, top_block) {
    mpm_list = [];
    left_mode = left_block.get_intra_mode(); // 强依赖：必须等左侧决出最终模式
    top_mode = top_block.get_intra_mode(); // 强依赖：必须等上方决出最终模式

    if (left_mode == top_mode) {
        mpm_list.push(left_mode, PLANAR, DC);
    } else {
        mpm_list.push(left_mode, top_mode, PLANAR);
    }
    return mpm_list;
}
🔍 为什么只看“左”和“上”，却能生成 3~6 个候选？
在实际的一帧画面中，CU（编码单元）是按从左到右、从上到下顺序编码的（Z-Scan 顺序）。当编码到当前 CU 时，只有它的左侧块和上方块已经完成了真实的 RDO 重建，其模式是确定的。

数量扩散逻辑（C-Model 严格推导）：
如果 Left 和 Top 模式不相同（例如 Left 是水平纹理，Top 是垂直纹理），说明当前块处于纹理交界处。此时 MPM 列表不仅会直接收录 Left 和 Top，还会兜底塞入无方向的 平滑模式（Planar） 和 均值模式（DC）。
如果在 VVC 等高级标准中，为了提高命中率，算法甚至会在 Left 模式的角度上做微调（例如 Left-1度, Left+1度），从而将候选列表膨胀到 6 个。这就解释了为什么 2 个输入源能裂变出 3~6 个候选。

硬件流水线瓶颈： 为了生成当前块的 MPM 列表，它必须死等左方和上方块彻底做完 RDO 并决出最终模式。在硬件上，这意味着相邻块之间存在强烈的模式层面的数据依赖，导致极长的等待时间和流水线气泡。

我们的 C-Model 做法 (区域冻结降级)：
通过走读代码发现，C-Model 在这块采用了和 Inter HMVP 高度一致的**区域冻结思路**。例如代码中的 ims->rdc32.mpm[i] = mpm[i] 逻辑，直接按 CU32 粒度提取并锁定了一组共享的 MPM。整个 CU32 内的子块强行复用这组冻结的 MPM，从而**彻底斩断了子块间互相等待 Intra 模式的流水线气泡**，实现了前端极致并发。

5. 痛点解析二：CCLM 引发的最长色度挂起

💡 什么是 CCLM (跨分量线性模型) 算法？
CCLM 是一种利用亮度 (Luma) 像素来预测色度 (Chroma) 像素的算法。它假设亮度和色度在同一个块内存在线性关系 (Chroma = α × Luma + β)。编码器通过对相邻的亮度重建像素和色度重建像素进行下采样和线性拟合，计算出参数 α 和 β，然后直接代入当前块的亮度重建像素求出色度预测值。

Chroma = α×L + β} LinearModel --> ChromaPred[生成: 色度预测块] style LumaRecon fill:#f5f5f5,stroke:#999 style Neighbor fill:#f5f5f5,stroke:#999 style LinearModel fill:#e1f5fe,stroke:#0288d1 style ChromaPred fill:#fff3e0,stroke:#f57c00

// CCLM Pseudocode (Algorithm Logic)
function cclm_predict(current_luma_recon, neighbor_luma, neighbor_chroma) {
    // 1. 根据相邻块重建像素计算线性参数
    (alpha, beta) = derive_linear_model(neighbor_luma, neighbor_chroma);

    // 2. 强依赖：必须等待当前块 Luma 走完 RDO 得到 Recon
    luma_downsampled = downsample(current_luma_recon);

    // 3. 执行跨分量线性预测
    chroma_pred = alpha * luma_downsampled + beta;
    return chroma_pred;
}

硬件流水线瓶颈： VVC 的 CCLM (跨分量线性模型) 要求色度的预测像素直接通过公式从亮度的重建像素 (Recon) 算出来。色度必须等亮度走完 T/Q/IQ/IT 拿到真实 Recon 后才能开始 Pred，极其阻塞流水线。

我们的 C-Model 做法 (原生规避)：
由于我们目前的架构主体依然是沿袭 HEVC 体系（部分融入优质工具），C-Model 中**并未引入 CCLM 这一宽带与流水线杀手特性**。这使得亮度和色度依然可以在拿到模式后，分别独立地进行后续计算，从算法源头上避开了这条最长的色度阻塞路径。

6. 痛点解析三：极小尺寸块的密集反馈噩梦

💡 什么是 ISP (Intra Sub-Partitions) 算法？
ISP 允许将一个常规的亮度预测块 (如 8x8) 沿水平或垂直方向强制切分为多个子块 (如四个 8x2 或 2x8)。最致命的是，这些子块在 CU 内部必须进行首尾相接的串行预测和重建：前一个子块的重建像素，必须立刻作为下一个子块的参考像素。

// ISP Pseudocode (Algorithm Logic)
function isp_process_cu(cu_block, num_subpartitions) {
    reference_pixels = cu_block.get_external_neighbors();

    for (i = 0; i < num_subpartitions; i++) {
        // 强串行：下一个子块的预测必须等待当前子块完全 Recon
        sub_pred = intra_predict(cu_block.sub[i], reference_pixels);
        sub_recon = rdo_and_reconstruct(sub_pred);

        // 致命依赖：当前子块的 Recon 会立刻变为下个子块的参考像素
        reference_pixels = update_neighbors_with(sub_recon);
    }
}

硬件流水线瓶颈： 连续的一堆 4x4 小块会导致极高频的串行反馈；而 VVC 的 ISP (帧内子划分) 会在一个 CU 内部再切分且首尾串行依赖，导致流水线深度崩溃。

我们的 C-Model 做法 (化繁为简)：
代码中明确标识了 //ISP not in，我们果断**舍弃了 ISP 这种导致强串行的算法**。对于标准的 4x4 块，我们的架构依靠强大的 MD 并发（原图粗选）掩盖了前期的搜索时间，并且 RDO 阶段只针对 Top-N（极少的候选数量）进行精确计算，将 4x4 带来的串行气泡时长压缩到了硬件可接受的极限。

7. 痛点解析四：多参考行 (MRL) 引发的 SRAM 带宽剧增

💡 什么是 MRL (Multiple Reference Line) 算法？
传统的帧内预测只允许使用紧挨着当前块最外面的一行/一列相邻像素作为参考。而 MRL 算法打破了这个限制，允许预测器跳过第一行，去拾取外围第 2 行或第 3 行的重建像素进行方向投影预测，以此来捕捉更远距离的纹理趋势。

// MRL Pseudocode (Algorithm Logic)
function mrl_predict(current_block, mrl_idx, angle_mode) {
    ref_pixels = [];
    // 内存带宽暴增：需要从 SRAM 取出更外围的整行/整列像素
    if (mrl_idx == 0) ref_pixels = fetch_sram_line(offset = 1);
    else if (mrl_idx == 1) ref_pixels = fetch_sram_line(offset = 2);
    else if (mrl_idx == 2) ref_pixels = fetch_sram_line(offset = 3);

    pred_block = angular_projection(current_block, ref_pixels, angle_mode);
    return pred_block;
}

硬件流水线瓶颈： 常规 Intra 只取外圈 1 行 1 列像素，但 VVC 的 MRL 允许使用外圈 3 行内的重建像素，导致 SRAM 读带宽需求成倍暴增，且连线极其复杂。

我们的 C-Model 做法 (克制引入)：
基于 PPA（面积与功耗）的极致权衡，当前的 C-Model 并未开启或引入 MRL。SRAM 只需要老老实实地缓存紧贴着边界的一行一列像素。这保证了线管系统（Line Buffer）的极简设计和可预测的超低内存带宽。
